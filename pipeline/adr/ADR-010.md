# ADR-010 — Deployment Target Strategy

**Resolves:** OI-CTX-09 (architecture portion) · **Status:** ACCEPTED · **Drives:** `apps/api`, `apps/worker`, `infra/`

## Context

`infra/docker-compose.yml` covers local dev only. Tenant #1's actual target
environment (cloud provider, container orchestration, CI/CD) is unknown
(OI-CTX-09).

## Options considered

**A. Commit to Kubernetes now** — build manifests/Helm charts as part of
early Build stories.
Pros: production-grade orchestration from the start; avoids a later
migration.
Cons: real upfront investment for an MVP whose entire point is proving the
governed-loop mechanics on one ticket, not infrastructure sophistication;
competes for effort with F-01 through F-20.

**B. Stay container-runtime-agnostic through MVP** — Docker Compose for
local dev (already built), a single deployable container image per app
(`apps/api`, `apps/worker`), no orchestration-specific manifests until a
real target (Tenant #1's, or a separately-chosen demo target) is known.
Pros: no wasted work if the eventual target differs from a guess made
today; keeps MVP focus on the governed-loop mechanics; a well-formed
container image is deployable almost anywhere with minimal adaptation.
Cons: "deploy this for real" isn't fully solved — a real gap remains
between docker-compose-local and production-reliable, deferred rather than
closed.

## Decision

**Option B** — stay container-runtime-agnostic through MVP, defer
orchestration-specific manifests until OI-CTX-09 resolves or a
demo-deployment target is separately chosen.

## Rationale

The discovery brief's "depth over breadth" directive and the MVP-narrowing
already done in Requirements Revision 2 both point the same direction —
don't front-load infrastructure sophistication the MVP doesn't need to
prove its four core architectural ideas. A clean container image is a
reasonable, low-regret intermediate artifact regardless of which
orchestration target eventually wins.

## Consequences

- **(+)** No wasted orchestration-specific work if the eventual target differs from a guess made today.
- **(+)** MVP Build stories stay focused on F-01 through F-20, not infra.
- **(–)** The "runs reliably against real traffic" gap remains open longer — must be revisited explicitly once OI-CTX-09 has an answer or before any real pilot goes live, not left indefinitely.
- **(–)** `infra/` currently has no deployment pipeline, only a lint/test CI workflow — worth flagging so it isn't mistaken for deployment automation.
